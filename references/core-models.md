# Core Models

## Emotional Forecast
Use when an experience feels flat, unfair, or incoherent. Map: **player prediction → event → feedback → revised prediction**. The useful design question is not “what happened?” but “what did the player believe could happen next?”

## Experience Bridge
Use when mechanics and fiction disagree. Align the player's verbs, the system's consequences, and the story meaning. A stealth narrative with rewards for indiscriminate combat has a broken bridge.

## Decision Field
Use when strategy is shallow or overwhelming. For each meaningful choice, record available information, viable options, costs, risks, counterplay, and feedback. More options are not automatically more depth.

## Readability Stack
Use when players cannot understand AI or system behavior. Layer: visible state, observable goal, telegraphed action, consequence, recovery. Favor behavior, space, animation, and sound before intrusive UI.

## Challenge Decomposition
Use when difficulty feedback is vague. Separate perception, reaction, planning, execution, and coordination. Tune the failing layer rather than applying global stat changes.

## Reward Expectation Loop
Use when retention mechanics, progression, or rewards are under discussion. Ask what future behavior each reward trains and whether the player will feel mastery or remorse afterward.

## Hypothesis Loop
Use for every prototype: **claim → smallest scene → player task → observable signal → threshold → keep/change/kill**. A prototype is evidence generation, not a miniature finished game.

## Dependency Stack
Use when scope grows or rework appears. Validate lower layers before content: sensing → state → goal choice → action → fallback → player-facing feedback.

## Decision Portfolio
Use for costly commitments. Rank decisions by impact, reversibility, dependency breadth, and evidence strength. Experiment before locking high-impact, irreversible choices.
